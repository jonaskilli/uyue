# 三层漏斗 · 真实小说匹配测试

用真实网络小说验证「分类正向 → 禁止 → 音效正则」三层漏斗的准确率，
找出**漏配**（该匹配没匹配）和**误配**（不该匹配却匹配），回头修正则。

---

## 1. 语料来源

| 项 | 值 |
|---|---|
| 数据集 | HuggingFace `wdndev/webnovel-chinese` |
| 许可 | Apache-2.0 |
| 下载方式 | Range 截取每个分片前 3MB（整体 4GB，无需全量） |
| 规模 | **12 本小说 / 3480 章** |

书目（覆盖都市、军事、玄幻、历史、奇幻、种田、悬疑、科幻、古玩）：

```
天下珍玩(510) 宠物天王(478) 舰娘之火力提督(392) 法师传奇(374)
武灵天下(360) 妖孽兵王(350) 三国大骗子(341) 装神弄诡(272)
路丝卡的银翼(235) -玄色(222) (种田文)无尽相思风(169) 001.天渊(4)
```

> 维基文库、kanunu8 等站点在本环境不可达，故选用 HF 数据集。
> 原始分片存于 `corpus/raw/`（30MB），索引后的章节在 `corpus/chapters.jsonl`。

## 3. 运行方式

```bash
cd test/tools

# ① 下载语料（首次，约 3 分钟）
python3 fetch_corpus.py 10 3

# ② 按分类选章节（每类 20 章）
python3 select_chapters.py                 # 全部 120 类
python3 select_chapters.py --domain A      # 只做 A 域
python3 select_chapters.py --per 20        # 每类 20 章

# ③ 跑匹配
python3 run_match.py --domain A            # 只跑 A 域
python3 run_match.py                       # 跑全部
python3 run_match.py --force               # 忽略已有结果重跑
```

**断点续跑**：已完成的分自动生成 `{cid}.summary.json`，重跑时自动跳过。
`PROGRESS.md` 每次跑完自动刷新，中断后看它就知道进度。

## 4. 判定逻辑（逐句，不跨上下文）

段落先切成句，再对**每一句独立**判定：

```
句子
 ├─ ① commonBlock.all − 本分类 commonExempt   命中 -> blocked_common
 ├─ ② classifyRegex（分类正向）               未命中 -> blocked_classify
 ├─ ③ blockRegex（分类禁止）                  命中 -> blocked_block
 └─ ④ 逐音效 regex 匹配
       命中 -> matched（记录命中的音效）
       否则 -> no_effect（潜在漏配，重点分析对象）
```

> **为什么切句**：`commonBlock` 的 222 个词源自大正则的「逐字扫描禁止」，
> 原语义是「句首到命中点之间不出现」，不是「段落里出现就禁」。
> 按段落判定会误杀 **60% 以上**（小说几乎每段都有「如果/已经/不能」）。

每个句子只依赖自身文本，**不拼接前后段落**，避免跨段误匹配。

> 结果文件已精简：`blocked_classify`（76%，与本分类无关的句子）每类只留 300 条，
> 其余四类（`matched`/`blocked_common`/`blocked_block`/`no_effect`）全量保留。
> 34 万条 → 11.6 万条，体积 87MB → 34MB。
> 完整统计仍保存在 `{cid}.summary.json`。

## 5. 已发现的问题与修正

### ① 通用禁用按段落判定 → 误杀 60%

```
修正前  A01: 段落2304  通用禁1505(65%)  命中5
修正后  A01: 句子5221  通用禁2167(41%)  命中7
```
改为**按句判定**。

### ② 音效正则「首2字|尾2字」并列 → 大量误配

```
(?:剑气入体|剑气|入体)  命中 "一道灵魂入体和一记雷电术"   ← 「入体」误配
(?:刀光一闪|刀光|一闪)  命中 "冷月枫突然眼中寒光一闪"     ← 「一闪」误配
```

根因：尾 2 字脱离主体后失去限定。高频尾 2 字统计：
`轻响(48) 落地(29) 提示(28) 开启(23) 呼吸(20) 展开(20) 打开(17)`

改为**共现约束**：

```
刀光一闪 -> (?:刀光一闪|刀光[^。？！？]{0,10}?一闪|一闪[^。？！？]{0,10}?刀光)
```

修正后 A01 误配 7 → 0。

### ③ 复用大正则时残留 bug 字符类

大正则主体开头是 `^(?:[^“”「」？.?!])*`（双引号/问号当硬边界）。
它不是预查，删预查时躲过了，已在复用流程单独补删。

### ④ 词表嫁接的语义错配（两轮修正）

想把大正则人工调好的主体词表用到音效上，第一版按「共享词最多」选规则：

```
剑划破空 -> (?:弩|箭|弯弓|拉弓|搭弓...)[^。？！]{0,12}?(?:剑划破空|破空...)   ❌
掌风破空 -> (?:弩|箭|弯弓|拉弓...)                                        ❌
棍棒破空 -> (?:弩|箭|弯弓|拉弓...)                                        ❌
```

凡带「破空」的音效都借到了弓弩规则——因为倒排把主体词表和动作词表混在一起。

修正：**建两个倒排**（前段主体 A / 后段动作 B），
按音效**首2字查 A 组（权重3）**、尾2字查 B 组（权重1），
且 `score < 3`（只有动作词对上）就不嫁接，宁可只用音效名。

```
修正前 嫁接 1967 个（大量错配）
修正后 嫁接 1083 个（主体对齐）
```

### ⑥ 通用禁用的作用位置错了（影响最大的一处）

第二版把 `commonBlock` 在**整句**上判定，拦截了 **40%** 的句子。
但大正则的原始语义是「**匹配点之前**」不含禁止词（逐字扫描禁止）。

```
全句判定： "他挥剑，如果敌人不退…"     含「如果」 -> 误杀 ❌
匹配点前： 匹配点在「挥剑」，前缀是「他」 -> 放行 ✅
```

改为在 `rx.search(p)` 后检查 `p[:m.start()]`：

```
修正前  通用禁 136,807 (40%)   命中 283
修正后  通用禁     151 (0.04%)  命中 401 (+42%)
```

### ⑤ 音效→分类覆盖不足

A01 命中长期为 0，排查发现不是正则问题，是**候选里就没几个音效**：

| 关键字 | 音效数 | 未归类 |
|---|---|---|
| 剑 | 86 | 41（48%） |
| 刀 | 46 | 20（43%） |
| 劈 | 6 | 5（83%） |

未归类但明显属于 A 域的：`万剑归宗`、`万剑齐发`、`人剑合一`、`剑域压制`、
`剑意凝形`、`刀法三连斩`、`刀劈空一次`、`刺刀拼杀`、`劈掌`、`戟劈`

未归类音效（1565 个）的高频字：`剑(41) 枪(35) 气(33) 灵(30) 药(28)` ——
集中在玄幻术法与丹药，说明 **C 域（玄幻术法）关键词缺失最严重**。

> 结论：正则再准，音效进不了候选也没用。
> 提升 `音效 → 分类` 覆盖率是当前收益最高的工作，优先于继续调正则。

## 6. 全量结果（120 个分类，每类 20 章）

```
句子总数   341,471
命中           325
未过正向   261,438   (77%)
分类禁止     9,633
无音效      69,652   ← 过了所有层但音效正则没匹配上
通用禁         187   (修正语义后，见问题⑥)
命中为 0 的分类  62/120
```

音效正则来源：`reused 61`（名称高相似整条复用）
`reused_broad 158`（词表匹配+同域+名称相似度≥0.2）
`grafted 649`（只借主体词表 + 自家动作词）
`generated 2962`（音效名全串+共现）

命中 top12：

| 分类 | 命中 | 句子 |
|---|---|---|
| C03 元素术法 | 61 | 1490 |
| H01 门窗 | 50 | 4425 |
| I06 船舶 | 21 | 1382 |
| H02 锁钥匙 | 17 | 1339 |
| N08 携带搬运 | 12 | 5382 |
| B05 护甲盾牌 | 11 | 1351 |
| C01 内力真气 | 11 | 1267 |
| I03 汽车 | 10 | 4159 |
| D06 饮食 / H12 清洁洗漱 / J05 学校 | 9 | — |

精度抽检（A04，质量好）：

```
['长剑出鞘'] <- "铿锵一声，长剑瞬间出鞘，握着长剑摇指前方"     ✅
['刀出鞘']   <- "拔刀出鞘，修长光亮刀身，圆滑流畅的弯曲幅度"    ✅
['匕首出鞘'] <- "抽出了靴子中，闪着锋利寒芒的匕首"（复用大正则）✅
```

### 结论：精度尚可，召回是当前唯一瓶颈

过了所有层的句子有 69,848 条，只命中 401 条（**0.57%**）。
即：分类层能找出相关描写，但**音效层的正则匹配不上**。

根因：**3830 个音效名覆盖不了小说的万千表达**。
「挥剑」「劈砍」「一剑刺出」这类描写，在音效库里没有字面对应的名字；
而自动生成的正则是从音效名派生的，名字对不上就匹配不到。

### 已尝试的提召回手段与效果

| 手段 | 命中 | 命中为0的分类 |
|---|---|---|
| 基线（音效名首尾2字并列） | 283 | — |
| 音效正则改共现约束 | 283（误配 7→0） | — |
| **通用禁用改「匹配点之前」语义** | **401（+42%）** | 52 |
| 纯整条复用（reused_broad 1388） | **561** | 48 |
| 纯嫁接（grafted 1083） | 290 | 69 |
| **分级复用（158 整条 + 649 嫁接）** | **325** | 62 |

**为什么放弃 561 那个方案**：纯整条复用召回最高，但多个音效共享同一条正则会
**语义漂移**——一个描写命中所有共享者：

```
D07「俯下身子」-> ['从床上缓慢坐起','从沙发起身','弯腰拾起小物']   ❌
F07「吐出烟圈」-> ['烟斗磕灰']                                  ❌
```

分级后（名称相似度 ≥0.2 才整条复用，否则只借主体词表）：

```
「俯下身子」不再误命中起坐类         ✅
F07「打火机…点烟」-> ['打火机点烟']   ✅
D07「单膝跪地」  -> ['跪地']         ✅
```

### 残留的误配（已知，未在本次解决）

集中在**短名音效**（core ≤ 2 字，无法用共现约束）：

```
H01['门'] <- "你当门神啊！"          ❌ 「门神」
N02['放下书包'] <- "…做为基地"        ❌ 词表含泛词「放下」
```

根因：2 字以下的名字只能整串匹配，缺少主体限定。
彻底解决需要给每个短名配歧义排除表（`门(?!神|派|牙|第)`），工作量大，留待后续。

## 7. 待办与可选路线

现状：**分类层可用，音效层召回过低（0.57%）**。可选三条路线：

### 路线 A：人工为高频音效写正则（质量最高，工作量大）

对 Top 200 高频音效，仿照 `ttsrv-replaces*.json` 的写法手写正则
（多元词表 + 语序双向 + 间隔限制）。预计能把召回提到 10~20%。
已有 61 个是复用现成大正则的，可直接作为模板。

### 路线 B：扩大多正则复用面（性价比最高）

目前只有 61 个音效复用了大正则（按名称 `Jaccard ≥ 0.5`）。
改成**按内容**匹配——用音效名的 2-gram 去撞大正则的词表，
可复用面能扩大一个量级。当前「词表嫁接」只嫁接了主体词表，
还没实现整条正则的复用。

### 路线 C：规则为主 + AI 兜底（务实）

- 规则层输出高置信结果（当前 401 条，精度较高）
- 规则未命中的段落，才调 AI（`aiEffectMatchMode = rules_then_ai`）
- 实测规则能覆盖的场景直接省钱，覆盖不了的仍有 AI 托底

**其余待办**

- [ ] 清洗分类正向词里的泛词：`出手`/`一道`/`开始`/`朝着`/`去`/`来`/`过`/`至`
      —— 导致大量无关句进入候选
- [ ] 52 个命中为 0 的分类逐个排查（部分可能是选章节不相关）
- [ ] 音效→分类覆盖率 80% → 90%+（剩余 762 个）
- [ ] 命中结果的**误配人工复核**（当前只抽检了 A04）

## 8. 已知的简化

原计划「每分类 10 本 × 20 章」（120 类 × 10 = 1200 本）不现实，
实际简化为：**每分类按相关度选出 top 20 章**（从 12 本 / 3480 章里选）。
若要增加书目，改 `tools/fetch_corpus.py` 的 Range 区间或增加分片即可。
