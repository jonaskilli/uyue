## 1. 现状：两条平行链路（这就是「忘了联动」）

```
【视觉特效链 · 段落级】
TTS/HttpReadAloudService 每段开头
  → postEvent(VN_PARAGRAPH)                HttpReadAloudService.kt:2184
  → scheduleDanmaku() 里的区间队列           BaseReadAloudService.kt:2327-2329, 2448-2461
  → SceneEffectGenerator.generateRange()    本地 EXTRA_RULES 为主 + 可选 AI(buildPrompt)
  → SceneEffectCue(para, kind, level, durationMs, indoors...)
  → SceneEffectStore.merge() → postEvent(SCENE_EFFECT_READY)
  → 三个 Dialog 订阅 VN_PARAGRAPH，para 锚点去重，postDelayed(1000L)
  → SceneEffectView.show(cue) → Choreographer → onDraw(canvas)
        老 8 种主类直画 / 其余 26 种 extraRenderer.draw()

【音效链 · 句子级】
① 正则：ttsrv-replaces3/5/4.json → applySoundEffectRules() 往正文插 "(爆炸音效)"
        → parseSoundEffects() → SoundEffect(charOffset, name, fileName)
② AI：AiEffectAnalyzer 两段式 → AiEffectPick(name, path, at, pos)
        → applyAiPicks() → SoundEffect(offsetRatio, isAiEffect=true)
  ↓ 汇合
每 200ms 的 checkAndPlayEffects()                 BaseReadAloudService.kt:1068-1074
  → checkRuleEffects():1122-1141  charPos >= charOffset - soundEffectOffsetChars
  → checkAiEffects():1144-1164   ratio >= offsetRatio - lead
  → effect.triggered = true → loadAndPlayEffect():1005-1020 → ExoPlayer
```

**五处具体断点：**

1. **粒度不同**：视觉是「段落 + 固定 1 秒延迟」，音效是「句子级 `charOffset` / `offsetRatio`」，所以会出现「音效响了画面没跟上」或反过来。
2. **门控不同**：视觉 AI 挂在 `danmakuEnabled`，音效 AI 挂在 `aiEffectEnabled`，`sceneEffectEnabled` 默认 false。
3. **AI 各调各的**：`DanmakuGenerator`、`SceneEffectGenerator`、`AiEffectAnalyzer`(2 次)、`BgmAIService` 共 4 条 AI 通道，各自缓存落盘，**没有共享语义对象**；`EventBus.kt:38-60` 里**没有音效触发事件**。
4. **词表各一套**：视觉 `EXTRA_RULES`(34 类) vs 音效 `ttsrv-replaces*.json` + `ai_effect_index_kw.json`（`正名|关键词`）；AI 音效阶段一的 `k[]` 场景关键词**用完即弃、不落盘**（`AiEffectAnalyzer.kt:339-375`），是最可惜的一块中间语义。
5. **没编译的参考包**：`scene-effects/` 的 74 预设 / 50 稳定 ID / 17 种 track 全在 app 之外。

## 2. 上一轮 129 个开源项目：有多少能「和之前一样」在屏幕上绘制

逐条判定见 `docs/visual_effects/开源项目_现有绘制层复用评估.csv`（129 行，含档位与接入方式）。精确统计：

| 档位 | 数量 | 含义 | 代表项目 |
|---|---|---|---|
| **A · 直接沿用现有 `SceneEffectView` 绘制层** | **33** | 纯 Android `Canvas`/`View` 粒子库、可移植的纯 JS 火焰/粒子算法、以及导出成透明序列帧/贴图后在 `onDraw` 里 `drawBitmap` 播帧的特效库与素材包 | `pixelfx`(序列帧)、`EffectMaterials`/官方示例(CC0 序列帧)、`kmpmedia OGSlash`(Kotlin 缎带算法)、`Leonids`、`androidx-particles`、`Particles-Android`、`Konfetti`、`ExplosionField`、`ParticleSmasher`、`FireWorks`、`SparkScreen`、`ViewExplosion`、`Grav`、`XView`、`doom-fire-algorithm`、`9am/fire-flame`、`yanhua`、Kenney Particle Pack、OpenGameArt VFX pack、`Pixel Art VFX Pack` 等 |
| **B · 加一个渲染后端，但仍挂同一个全屏浮层** | **39** | Lottie / PAG / 透明视频 / 动图 / WebView / GLSL，容器生命周期（`show`/`clear`）可以复用，但要新增解码或 GL View | `lottie-android`、`libpag`、`AlphaPlayer`、`Tencent/vap`、`APNG4Android`、`tsParticles`、`canvas-confetti`、`fireworks-js`、`PixiJS`、`ShaderView`、`android-gpuimage`、`Burning-Flame2.0`、`Effekseer` 运行时等 |
| **C · 需要换 UI 栈/引擎/平台，不建议直接复用** | **41** | Compose / AGSL、Flutter、iOS、RN、Unity/Godot/libGDX 等；只参考算法与参数 | `Vortex`、`newton`、`flutter_fireworks`、`ConfettiKit`、`ParticleEffectForUGUI`、`cocos2d-x` 等 |
| **N · 非绘制（语义触发参考 / 索引）** | **16** | 不参与绘制 | WebGAL、Ren'Py、本项目 `scene-effects/`、AndroidLibs 索引、GitHub topics 等 |

**结论：**
- 「和之前那个一样、直接在 `SceneEffectView.onDraw` 里画」= **33 个**；
- 「仍挂同一浮层、只是多一层播放/渲染后端」= **39 个**；
- **合计 72 个能落到当前 Android 项目**，其中 A 档是零新增引擎、改动最小的。

**更重要的发现**：你现有 34 种 `SceneEffectKind` 里**已经有** `FIRE`(:94)、`FIREWORKS`(:93)、`LIGHTNING`、`SPARKLES`、`COMIC`、`ANGER`、`SMOKE`、`RAYS`，`SceneEffectExtraRenderer` 里已有 `drawFire / drawFireworks / drawSymbol`。所以「火焰 / 爆炸」的**绘制器本来就写好了**，缺的只是：
1. 更专门的 `EXPLOSION`（冲击环 + 碎片 + 闪光）和 `SLASH`（刀光斩击）两个 kind；
2. **让它在音效响的那一句出现**，而不是段落开头延后 1 秒。

## 3. 触发方案（核心）

### 3.1 设计原则

- **不新增 AI 调用、不新建第二套语义分析、不改正则/AI 音效的播放逻辑**；
- 把视觉特效拆成两类：**Ambient（持续型：雨雪雾、星空，保持现有段落级）** 与 **Burst（瞬时型：爆炸、火焰蹿起、刀光、命中闪光，跟音效同句）**；
- 音效命中处是唯一「真正触发」的收口，在那里发一个事件即可，不需要等音频下载完成。

### 3.2 方案 A（推荐 MVP）：音效命中即画

**① 新增事件与载荷**

- `EventBus.kt` 增加 `SOUND_EFFECT_FIRED = "soundEffectFired"`。
- 新增 `SoundEffectFired(para: Int, ratio: Float, name: String, fileName: String, isAiEffect: Boolean, charOffset: Int)`（放 `model/SceneEffectModels.kt` 或新文件）。

**② 发起点（3 处，都在 `BaseReadAloudService.kt`）**

| 位置 | 时机 |
|---|---|
| `:1135-1140` `checkRuleEffects()` | `effect.triggered = true` 后、`loadAndPlayEffect(effect)` 前 `postEvent(SOUND_EFFECT_FIRED, ...)`，带上刚算出的 `ratio`/`charPos` |
| `:1157-1163` `checkAiEffects()` | 同上，带 `ratio` 和 `effect.offsetRatio` |
| `:1115-1119` `drainMissedAiEffects()` | 补播队列也要发，否则「识别晚了的音效」只有声音没画面 |

> 注意：`loadAndPlayEffect():1005-1020` 会起 IO 协程下载/解码音频，**画面不能等它**；事件必须在 `triggered = true` 的同一刻发，用当前播放进度做锚点。

**③ 映射层：音效名 → 画面效果**

新增 `SoundEffectSceneMapper`（建议放 `model/`），**复用现成词表，不另建一套**：

- 输入 `effect.name`（规则音效就是 `(爆炸音效)` 里的「爆炸」；AI 音效是 `AiEffectPick.name`，如「剑鸣」「拳击」「火焰」）与 `fileName`（AI 库相对路径，含 `拟音/`、`自然/` 等类目）；
- 词表来源：`SceneEffectGenerator.EXTRA_RULES`（现有 34 类关键词）+ `app/src/main/assets/ai_effect_index_kw.json`（`正名|关键词`，`AiEffectIndex.Entry.keywords` 已在用）；
- 输出 `SceneEffectKind` 或新增 `fxId`（`fx_explosion` / `fx_fire` / `fx_slash` / `fx_impact` / `fx_shockwave`），带 `level` 和 `durationMs`（瞬时 600~1200ms）。

**④ UI 侧订阅（三处都要改）**

- `ReadAloudDialog.kt:1887` `observeLiveBus()`、`VnStageDialog.kt:254`、`FullscreenAiImageDialog.kt:220` 各加一条：
  ```kotlin
  observeEvent<SoundEffectFired>(EventBus.SOUND_EFFECT_FIRED) { e ->
      if (!AppConfig.sceneEffectEnabled) return@observeEvent
      val cue = SoundEffectSceneMapper.map(e) ?: return@observeEvent
      binding.sceneEffectView.burst(cue)   // 新 API，瞬时、不进 Store、不占 para 锚点
  }
  ```
- `VN_PARAGRAPH` 订阅（`ReadAloudDialog.kt:1921-1937` 等）**保留**，但只负责 Ambient；把 `postDelayed(1000L)` 保留给天气类（避免剧透），瞬时 Burst 不走延迟。

**⑤ `SceneEffectView` 增加瞬时层**

- `SceneEffectView.kt` 新增 `activeBursts: MutableList<Pair<SceneEffectCue, Long>>` + `burst(cue)`；`onDraw():342-376` 末尾统一画 bursts（与 `currentCue` 并存，不互相打断）；`clearSceneEffects():320-325` 同时清 bursts；`show()` 的同 kind 合并逻辑只作用于 Ambient。
- 去重节流：`para + name + source` 3 秒内只触发一次；同 group 互斥（爆炸/火焰不同时叠）；同屏最多 2 个 burst；`sceneEffectEnabled` 关时不发；省电/「移除动画」时跳过强闪光类。

### 3.3 方案 B（中期，省一半 AI 调用）：一次 AI，多方消费

- `AiEffectAnalyzer.kt:339-375` 阶段一产出的 `k[]`（1~2 字场景关键词）目前**不落盘** → 落进 `ParagraphSemantic(para, keywords[], picks[], cues[])`；
- 把 `SceneEffectGenerator.buildPrompt()` 与 AI 音效两条 Room 提示词合并成一次调用，输出 `{para, cues:[{kind,level}], picks:[{name,pos}]}`；
- 视觉 / 音效 / 弹幕 / BGM 都消费同一个 `ParagraphSemantic`。收益：少一次 AI、语义一致、词表只需要一份。成本：改 3 处提示词 + 解析 + 缓存版本。
- **当前不建议先做**：方案 A 不改任何 AI 就能解决同步问题，先验证效果再决定是否合并。

### 3.4 方案 C（长期）：把 74 预设 / 50 稳定 ID 搬进 app

把 `/workspace/scene-effects/` 的 `SceneEffectResolver` + `effects.json` + `semantic-cues.json` 落地，用「稳定 ID → tracks」替换 Kotlin 枚举，让视觉特效像音效规则一样**可编辑、可导入、可缓存**。改动最大，等前两步稳定后再做。

### 3.5 触发优先级与降级

| 优先级 | 来源 | 粒度 | 用途 |
|---|---|---|---|
| 1 | 正则/朗读脚本插入的 `(爆炸音效)` → `SOUND_EFFECT_FIRED` | 句子级 `charOffset` | Burst（最精确） |
| 2 | AI 音效 `AiEffectPick` → `SOUND_EFFECT_FIRED` | 句子级 `offsetRatio` | Burst |
| 3 | `EXTRA_RULES` 本地关键词 | 段落级 | Burst 兜底（音效关时仍能画） |
| 4 | `SceneEffectGenerator` AI 增强 | 段落级 | Ambient（雨雪雾、星空） |
| 5 | 14% 环境兜底 `ambientFallback()` | 段落级 | 轻量氛围 |

降级链：音效开 → 跟音效同句；音效关/AI 未配置 → 退回本地关键词段落级；`sceneEffectEnabled=false` → 全部不画。

## 4. 绘制方案：完全沿用原来的 `SceneEffectView`

### 4.1 扩展点（只动这几行）

| 文件 | 位置 | 改动 |

### 4.2 三档项目怎么接

- **A 档（33 个，零新增引擎）**
  - 纯算法类（`doom-fire-algorithm` 几十行、`9am/fire-flame`、`Proton`、`particles.js`、`tsParticles` 的粒子公式）→ 直接把公式抄进 `SceneEffectExtraRenderer` 的新 `drawXxx()`，沿用现有的 `fade / ambientBase / Canvas / Paint`，与站点原版写法一致（现有 26 种就是这么来的）。
  - Android 原生 View 类（Leonids / Konfetti / FireWorks / ParticleSmasher / SparkScreen …）→ 不引依赖，把 `Particle` 数据类 + 发射器循环抄进来当参考；它们的 `View` 壳不要，用现有 `SceneEffectView` 的帧循环。
  - 序列帧/贴图类（`pixelfx`、`EffectMaterials`、Kenney CC0、OpenGameArt VFX pack）→ 放 `app/src/main/assets/fx/`，用 `:327-340` **现成的 `sprite()`**（`drawBitmap` + 旋转缩放 alpha）加一个 `FxSpritePlayer(frameRects, durations)` 播帧即可：
    ```kotlin
    // 只示意，落在 SceneEffectExtraRenderer 内
    val frame = ((t * fps).toInt() % frames.size)
    sceneEffectView.drawSprite(c, bitmap, frameRect[frame], px, py, scale, alpha)
    ```
    这样 244 个 pixelfx 特效、CC0 素材包全都复用同一个浮层和同一个 `show/clear` 生命周期。
- **B 档（39 个）**：Lottie/PAG/AlphaPlayer/透明视频/WebView/GLSL 各自是一个独立 View，**叠在 `SceneEffectView` 同一层级**（布局里加一个 `FrameLayout` 容器），但生命周期统一由三处 Dialog 的 `initSceneEffect()` / `clearSceneEffects()` 管理；低端机默认不开。
- **C 档（41 个）**：只参考算法、参数与素材，不引入 Compose/Flutter/Unity。

### 4.3 性能与降级（沿用现有做法）

- 帧循环继续用 `Choreographer`(`SceneEffectView.kt:287-293`)，`currentCue == null && bursts 空` 时立刻 `removeFrameCallback`，不常驻；
- 贴图预解码并复用 `Bitmap`，不在 `onDraw` 里 `new`；粒子用确定性伪随机（`ambientBase()` 已是这个思路），旋转屏幕不跳变；
- Burst 时长 600~1200ms、同屏 ≤2 个；Ambient 仍受 `level.coerceIn(1,4)` 与 `countFor()` 上限 600 约束；
- 系统「移除动画」/省电模式跳过闪光与震屏（目前 app 内**尚未实现**，可顺手补）；
- 切章（`ReadAloudDialog.kt:1902-1911`）、暂停、拖动进度时清空瞬时层，避免补播残留。

### 8.1 触发方案定案：**联动已有代码，不单独做一套**

先把三处现有实现的实际形态看清楚了，再做的判断：

| 现有物 | 实际内容 | 处理方式 |
|---|---|---|
| 正则音效替换规则 `ttsrv-replaces*.json` | `pattern` / `replacement`，replacement 往正文里插 `(爆炸音效)` 之类的标记，`parseSoundEffects()` 再提取出 `SoundEffect(charOffset, name, fileName)` | **不改**。它已经把语义写进 `name`，画面直接消费这个字段即可；新增/修改一条规则会自动带出对应画面 |
| AI 音效索引 `app/src/main/assets/ai_effect_index_kw.json`（323KB） | 每行 `正名|关键词|关键词...`，供 AI 音效阶段二检索候选音效；`AiEffectPick.name / path` 是它的输出 | **不改**。这是音效检索配置，不是画面配置；若往里加画面字段会污染音效候选、破坏既有 AI 结果 |
| AI 音效两条 Room 提示词「音效关键字提取」「音效选择」 | 输出关键词与 `{name,path,at,pos}`，与音效库强绑定 | **不改**。改提示词等于要重测整套音效 |
| `BaseReadAloudService.loadAndPlayEffect(effect)` | 规则音效、AI 音效、补播队列**三条路径的唯一收口** | **在这里挂一个事件**，一处覆盖全部触发源，且在下载音频之前同步发，画面与音效同句 |

## 9. 全量音效名提取 + 一个效果绑定多个音效（2026-11-05 追加）

### 9.1 先回答「你现在是这样的吗」

**改动前不是。** `SoundEffectSceneMapper` 当时只是对每个画面 kind 配了一组**模糊关键词**，靠 `name.contains(关键词)` 判断；虽然多个音效都能触发同一个效果，但没有显式的「音效名 → 效果」绑定表，也无法逐个查看/编辑某个效果到底绑了哪些音效。

**现在改成了「一个效果绑定多个真实音效名」**：只要绑定的任意一个音效被触发，画面立刻在同一句绘制，精确匹配优先、关键词兜底。

### 9.4 触发链路（现在是精确优先）

```
音效触发 → loadAndPlayEffect() → SOUND_EFFECT_FIRED(name, fileName, ...)
  → SoundEffectSceneMapper.map()
      ① normalize()：(爆炸音效) / 爆炸.mp3 / 01_通用母库/拟音/地雷爆炸.mp3 → 统一名字
      ② 查 fx_sound_bindings.json 精确表（懒加载一次，502 条 HashMap，O(1)）
      ③ 未命中 → ≥2 字具体词兜底（单字泛词不参与，避免「倒车雷达」画闪电）
  → SceneEffectCue(burst=true) → 三个弹窗 → SceneEffectView.burst() → 画面
```

`(爆炸音效)` → `爆炸` → `EXPLOSION`；`火焰音效` → `FIRE`；`拔刀音效` → `SLASH`；`地雷爆炸.mp3` → `EXPLOSION`；`军刀出鞘` → `SLASH`；`内力比拼` → `SHOCKWAVE`。全部实测命中。

**改绑定不用改 Kotlin**：直接编辑 `fx_sound_bindings.json` 里对应效果的数组，增删音效名即可；空数组的效果表示音效库里没有对应名字，靠关键词兜底。
