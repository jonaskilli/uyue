# 视频源开发指南（时光播放器 · 唯一链路）

> 适用项目：本仓库基于 Legado 阅读 3.0 的分支 `yuedutts`，视频链路为 `SourceVideoPlayerActivity` + `FullscreenVideoPlayer`（时光播放器）。
> 本文档由原《时光播放器书源适配指南》（根目录）与《docs/视频源开发指南》于 2026-11-12 合并而来，是**唯一**的视频源编写规范。
> **本项目只以时光播放器为目标**：书源必须让每集在首次解析就拿到可直接交给 ExoPlayer 的流地址；内置的旧播放器、网页播放器兜底不作为书源设计目标（见 §1.3）。
> 代码基线：2026-11-12。

---

## 0. 一句话结论

**时光播放器要的是「每集一个可以直接交给 ExoPlayer 的流地址」。** 书源必须做到：目录里的章节 URL 是普通 `http(s)` 地址；执行正文规则后返回**只有一个 URL 的字符串**；且这个 URL 能被 `isPlayableUrl` 判定为可播流。

给其它 AI 的最短指令：

> 请按 `docs/视频源开发指南.md` 写视频书源。要点：`bookSourceType=4`、分组含「视频」；章节 URL 必须是普通 https 地址；`ruleContent.content` 必须返回**单个** `.mp4/.m3u8/.m4v/.webm` 直链（不能是 HTML、JSON、MPD 文本、提示语）；用 `result = 直链; result;` 收尾；目录/列表 `<js>` 返回 `JSON.stringify` 后的字符串数组；不要用 `java.startBrowser*`、不要用 `data:` URI、不要依赖 jsLib 或私有 java 扩展；`header` 用静态 JSON 并带 `User-Agent` + `Referer`；**优先用站点 JSON API 生成目录和取流，别依赖页面 DOM**。

## 1. 硬规则速查表

| # | 规则 | 违反后果 |
|---|---|---|
| 1 | `bookSourceType = 4`，`bookSourceGroup` 含「视频/影视/短剧」 | 不进时光播放器，走普通阅读页 |
| 2 | 章节 URL（`chapterUrl`）必须是**普通 http(s) 地址** | `data:` URI 请求失败、正文返回空 |
| 3 | `ruleContent.content` 只返回**一个 URL 字符串**，路径以 `.mp4/.m3u8/.m4v/.webm` 结尾（或含 `/m3u8/`、`authPath`、`.m3u8?`） | 判不出直链 → 兜底/内置浏览器 |
| 4 | 正文里不要出现多余文字、HTML、JSON 对象、`<MPD ...>`、提示语 | 同上；时光播放器不支持 MPD |
| 5 | 正文、登录检查、公共库里**不要**调 `java.startBrowser()` / `java.startBrowserAwait()` | 拦截窗口记下网页 → `webPlayerUrl` → 嗅探 → 内置浏览器 |
| 6 | 不要依赖 `jsLib` 自定义函数、`java.readBookConfig`、`Map("cookie")` 等其它 App 的私有扩展 | 规则抛异常被吞 → 正文空 |
| 7 | `header` 用**静态 JSON 字符串**，必须带 `User-Agent`（桌面 UA 更稳）和 `Referer` | 直链取流 403 → `Source error` |
| 8 | `chapterList` / `bookList` 用 `<js>` 返回数组时，每条必须 `JSON.stringify({...})` | Rhino 对象数组无法被 `$.name` 取值 |
| 9 | 不要把直链型源加进 `videoSourceWhitelist` | 会走书源自带播放器（内置浏览器），不符合本项目目标 |
| 10 | `bookUrl` 必须是普通 https 详情页/API 地址，且 `ruleToc` 能从它的响应生成分集 | 目录为空 → 无集可播 |
| 11 | **优先用站点 JSON API 生成目录、取流地址**，不要依赖页面 DOM | 页面改版/视图参数变化时 DOM 完全不同，目录和播放一起失效 |
| 12 | `bookUrl` 与每个 `chapterUrl` 必须保持**同一视图参数/请求头** | 目录能出，但正文请求拿到拦截页（年龄门/验证页） |

### 1.3 只使用时光播放器：文档口径与代码现状

- **写源口径**：只允许「返回直链」这一种成功路径。任何「让书源拉起网页播放器、App 自己看」的写法都视为**失败设计**，不要写进新源。
- **代码现状**：解析拿不到直链时仍存在兜底 `fallbackIndex → playWithSourcePlayer() → VideoSourcePlayer.play() → startBrowser(videoMode=true)`，会打开全屏 `WebViewActivity`。这是历史遗留的失败路径，**不是书源该依赖的能力**。
- **彻底关闭兜底**：书源管理右上角「禁止弹出验证/内置浏览器」勾选后，`SourceVerificationHelp.startBrowser()` 会直接抛异常，兜底浏览器不再弹出，只显示失败提示（`SourceVerificationHelp.kt:100`）。不勾选时维持旧行为。
- 白名单 `videoSourceWhitelist`、类型 C（网页播放器）、`VideoPlay.kt` 的旧播放器链路均属历史兼容，本文档不再把它们列为可选方案。

## 2. 时光播放器播放链路（代码级）

### 2.1 入口识别

`BookSourceExtensions.isVideoSource()` / `BookSourceDao.flowVideoSources()`（`BookSourceDao.kt:440`）三重判定，满足其一即视为视频源：`type = 4`、分组含「视频/影视/短剧」、`ruleContent` 序列化后含 `.m3u8|.mp4`。从发现页/搜索点进去走 `ExploreShowActivity.playVideo()` → `SourceVideoPlayerActivity`。

> 识别口径两处必须一致；新源请**同时**设 `bookSourceType=4` 并让分组名带关键词。

### 2.2 目录构造（`SourceVideoPlayerViewModel.loadInternal`）

- 若 `chapter.url` 本身 `isPlayableUrl() == true`，这一集**零请求直接播**。
- 请求头来自 `source.getHeaderMap(true)`，后面原样传给播放器。
- 目录顺序 = 章节顺序；进度按 `bookUrl + 章节序号` 记忆；竖滑切集要求目录 ≥2 集，单集电影也支持。
- 白名单源在当前代码里会先探测一次直链，但**写新源不要依赖这条探测**（见 §1.3）。

### 2.3 每集解析（`VideoSourcePlayer.resolveChapter`，`:319`）

```
begin(interceptBrowser = true)          // 开启拦截窗口
runRule() → WebBook.getContentAwait()   // Rhino 执行 ruleContent（每次先跑 loginCheckJs）
end() → intercepted                     // 期间书源调过的 startBrowser 地址

direct    = intercepted（若 isPlayableUrl） ?: playableFromContent(content)
webPlayer = if (direct == null) intercepted else null
```

- 第一次两者都空会**自动补跑一次规则**（兼容历史「请刷新查看内容」型源，新源不要依赖）。
- `runRule()` 会吞掉规则异常返回空内容，所以书源抛错**不会看到明确报错**，只表现为「正文返回空」。

| 结果 | 走向 |
|---|---|
| `directUrl` 非空 | ✅ 更新 `episodes[index].uri` → `FullscreenVideoPlayer` / ExoPlayer（手势切集、预缓存、下载全部可用） |
| `webPlayerUrl` 非空 | 后台 `VideoUrlSniffer.sniff()` 用真实 WebView 抓媒体请求；钓到交 ExoPlayer，钓不到 → 兜底 |
| 两者都空 / 异常 | ❌ `fallbackIndex` → 内置浏览器（见 §1.3），勾选开关后改为失败提示 |

### 2.4 可播地址判定（`VideoSourcePlayer.isPlayableUrl`，`:108`）

```kotlin
url 必须以 http 开头
path = url 去掉 ? 和 # 后的部分（小写）
命中任一即 true：
  path.endsWith(".m3u8" | ".mp4" | ".m4v" | ".webm")
  url 含 "/m3u8/" / "authPath"（忽略大小写） / ".m3u8?"
```

`extractPlayableUrl`（`:122`）：正文 `trim()` 后以 `http` 开头则取第一个空白前的片段再判定；否则正则找第一个 `http...`。
`playableFromContent`（`:348`）：命中即返回；否则若**正文整体是一个裸 URL（无空白）**，真发一次请求用 `VideoUrlSniffer.isMediaUrl` 探测 Content-Type（给 `?url=xxx.m3u8` 这类代理直链兜底）。

> ⚠️ 最稳的写法：**只返回一个 URL，前后不要有任何字符**。

### 2.5 请求头如何到播放器

`FullscreenVideoPlayer.buildMediaSourceFactory()`（`:915`）：

```kotlin
val httpFactory = DefaultHttpDataSource.Factory().setAllowCrossProtocolRedirects(true)
if (headers.isNotEmpty()) httpFactory.setDefaultRequestProperties(headers)
```

`headers` 来自书源 `getHeaderMap(true)`。**当前代码只有 `setDefaultRequestProperties`，没有单独的 `setUserAgent` 调用**——UA 靠 `header` 里的 `User-Agent` 作为默认请求属性传入。旧版文档曾写「已加 `setUserAgent`」，按当前代码已更正；因此 `header` 里写对 UA 尤其重要。

`header` 写成 `@js:` 时由 `BaseSource.evalJS()` 执行，绑定只有 `java`、`source`、`cookie`、`cache`、`baseUrl` 等，**不保证 jsLib 已加载**；建议直接写静态 JSON。

### 2.6 兜底路径（只作为失败诊断，不是书源目标）

`SourceVideoPlayerActivity`：`LaunchedEffect(state.fallbackIndex)` → `playWithSourcePlayer()` → `VideoSourcePlayer.play()`（`:237`）：

```kotlin
val url = launched ?: content.trim().takeIf { it.startsWith("http", ignoreCase = true) }
if (url != null) {
    SourceVerificationHelp.startBrowser(..., videoMode = true, preloadUrl = book.tocUrl)
    return true
}
throw IllegalStateException("书源未拉起播放器，也没有返回播放地址。\n\n正文返回：\n...")
```

即：**解析失败且正文/拦截记录里有一个 `http` 开头的字符串，就会被当网页塞进内置浏览器**；连字符串都没有就抛「获取播放地址失败」。勾选「禁止弹出验证/内置浏览器」后，`startBrowser` 直接抛异常，此路径不会再弹界面。

## 3. 规则语法（Rhino 引擎，不是浏览器）

### 3.1 ES5 限制

| 写法 | 可用性 |
|---|---|
| `var`、`function`、`String`、`RegExp`、`match/replace/split/indexOf/substring` | ✅ ES5 |
| `JSON.parse` / `JSON.stringify` | ✅ |
| `java.ajax`、`java.post`、`java.startBrowser*`、`cache.get/put`、`baseUrl`、`result`、`book`、`title`、`source`、`cookie`、`chapter` | ✅ 引擎注入 |
| `new URL(url, base)` | ❌ Rhino 没有；用字符串拼接补全相对地址 |
| `fetch`、`XMLHttpRequest`、`document`、`window` | ❌ 用 `java.ajax` / `java.post` |
| 数组 `includes/find`、箭头函数、模板字符串 | ⚠️ 不保证；用 `indexOf` + `function` |

相对地址补全（代替 `new URL`）：

```js
var base = String(baseUrl);
var cut = base.indexOf('/', 8);              // 跳过 https://
var root = cut > 0 ? base.substring(0, cut) : base;
var abs = root + relativePath;               // relativePath 以 / 开头
```

### 3.2 URL/字段插值（极易混淆）

| 写法 | 用在哪 | 效果 |
|---|---|---|
| `{$.field}` | **规则字段**（如 `ruleSearch.bookUrl`） | ✅ JSON 模式下内嵌 JSONPath |
| `{{js代码}}` | `searchUrl` / `exploreUrl` | ✅ `{{key}}`、`{{page}}` 同机制 |
| `{{$.field}}` | URL 的 `{{}}` 里 | ❌ 无效 |

正确示例：`"bookUrl": "https://api.xxx.com/detail?ids={$.vod_id}"`。
写错时 URL 会带字面 `{$.vod_id}` 去请求 → 404 → **目录列表为空**（搜索结果却正常，极具迷惑性）。

### 3.3 `@js:` 规则的返回值

**统一写法：`result = 结果; result;`**

```js
@js:
var d = JSON.parse(result);
var r = JSON.parse(java.ajax('https://api.example.com/resolve?id=' + d.data.id));
result = r.url;      // 必须是单个可播直链
result;
```

- 规则结果取 `AnalyzeRule.evalJS()` 里 `script.eval(...)` 的返回值；绑定变量里也有 `result`。把最终值赋给 `result` 并以 `result;` 收尾，是本项目所有已验证书源的一致写法，也便于调试时对照「正文返回：xxx」。
- `(function(){ ... return x; })()` 这类 IIFE 在 Rhino 里作为脚本最后一个表达式，理论上也能取到返回值，但**不推荐**：可读性差、与其它规则风格不一致、出问题时难定位。

### 3.4 目录 / 列表的 `<js>` 返回值

必须返回**字符串数组**，每条是 `JSON.stringify` 后的 JSON：

```js
<js>
var out = [];
for (var i = 0; i < list.length; i++) {
    out.push(JSON.stringify({ name: list[i].title, url: list[i].apiUrl }));
}
out;
</js>
```

配套 `"chapterName": "$.name"`、`"chapterUrl": "$.url"`（发现/搜索对应 `$.bookUrl` 等）。
❌ 直接 `out.push({name:...,url:...})`：Rhino 的 `NativeObject` 上 `$.name` 取不到值。

`chapterList` 的 JS 里 `result` 是目录页原始响应文本（字符串），JSON API 直接 `JSON.parse(result)`。

### 3.5 `@CSS:` 与网络请求

- `@CSS:` 前缀只是把规则切成 CSS 选择器交给 Jsoup（`AnalyzeByJSoup.SourceRule`，`:516`），`a.class`、`tag.class` 都是合法选择器；但**页面 DOM 易变，能走 API 就别用它**（§4）。
- `java.ajax(url)`：GET，返回响应体字符串。
- `java.post(url, body, headers)`：POST，返回 `Connection.Response`，用 `.body()` 取响应体、`header('X')` 取响应头。headers 直接传 JS 对象即可，例：

```js
var r = java.post('https://api.example.com/playback', '{}', {'Content-Type':'application/json'});
var j = JSON.parse(String(r.body()));
```

本项目 `bookSource_抖音_时光播放器专用.json` 已在用这种写法。
- `ruleContent.sourceRegex`（如 `.*\.(m3u8|mp4|flv).*`）用于校验正文提取结果，建议写上，防止网页文本被误当播放地址。

### 3.6 页面字段兜底

同一站点的分集页与电影页字段可能不同（例如 `url_next` 有值 / 为空，真实地址在 `player_aaaa.url`）。规则必须**多字段兜底**，只依赖单一字段会让某类内容全挂。

## 4. 页面版本与软风控（最容易翻车的一节）

**HTTP 200 ≠ 能解析。** 同一个路径带不带查询参数、带什么 UA/Cookie，可能返回完全不同的页面：

| 请求 | 状态码 | 响应 | 分集元素 |
|---|---|---|---|
| `/video/12988/` | 200 | 72KB 年龄确认页（`hg-age-modal` 出现 44 次） | **0 个** |
| `/video/12988/?__view=mobile` | 200 | 275KB 完整播放页 | 3 个 |

这类「返回 200 但内容是年龄门 / 验证页 / 桌面版」属于**软风控**，只看状态码查不出来。写源和自查时必须：

1. **用书源真正拼出来的 URL**（含全部查询参数、带书源 `header`）去验证，不要用随手复制的链接；
2. 对比**响应体积 + 特征 DOM / JSON 字段**，确认规则要匹配的东西确实存在；
3. `bookUrl` 与每个 `chapterUrl` 保持**同一视图参数**（如 `?__view=mobile`），否则目录能出、正文请求拿到的是拦截页；
4. **优先用站点 JSON API**：DOM 会随版本/参数变，`/api/videos/{id}` 这类接口稳定得多。目录从 `episodes` 数组生成、播放地址从 playback 接口取，能免疫大部分页面改版；
5. 需要会话 Cookie 的源开启 `enabledCookieJar: true`，或在目录/详情阶段先访问一次站点首页；遇到 412/403 等硬风控时补保底匿名 Cookie（B 站 `view/playurl` API 不带 Cookie 返回 412，带 `buvid3` 即 200）。

**实测教训（B 站 CDN 请求头）**：

| 请求头组合 | 直链 Range 结果 |
|---|---|
| 桌面 UA + Referer | 206 |
| 移动 UA + Referer | 403 |
| 仅 Referer / 仅桌面 UA | 403 |

所以 `header` 里 UA 与 Referer 必须同时写对。

### 5.2 正文按章节 URL 分支（`@js:`）

```js
@js:
var u = String(baseUrl);
var d = JSON.parse(result);
var s = '';
if (u.indexOf('/api/movie/play') >= 0) {
    s = (d.data.durl && d.data.durl[0]) ? d.data.durl[0].url : '';
} else if (u.indexOf('/api/live/play') >= 0) {
    s = d.data.hls_url || '';
} else {
    s = d.data.url || '';
}
result = s;
result;
```

### 5.3 正文需要 POST 换出地址（推荐写法）

章节 URL 仍是普通 https；正文从 `baseUrl` 抠出业务 id / 集号，POST 播放接口，取 `data.streams.main`：

```js
@js:
var u = String(baseUrl||'');
var m = u.match(/\/video\/(\d+)\/(?:ep-(\d+)\/)?/);
var id = m ? m[1] : '';
var ep = m ? (m[2] || '1') : '1';
var link = '';
if (id) {
    var r = java.post('https://api.example.com/api/videos/' + id + '/episodes/' + ep + '/playback',
                      '{}', {'Content-Type':'application/json'});
    var j = JSON.parse(String(r.body()));
    link = (j.data && j.data.streams && j.data.streams.main) || '';
}
result = link;
result;
```

要点：
- `auth_key` / 带时效的直链**不要缓存**，正文规则每次播放都会重跑，天然每次重新取；
- 第 1 集常无 `ep-N` 段，兜底集号 `1`；必要时再从 `result`（HTML）里抠 `data-play-id` 补 id；
- 先确认 POST 接口在**不带 UA/Referer** 时也能 200，避免把风控问题误判成规则问题。

### 5.4 目录 `<js>` 处理多 P / 合集

```js
<js>
var out = [];
var p = JSON.parse(result).data;
function push(name, url) { out.push(JSON.stringify({name: name, url: url})); }
for (var i = 0; i < (p.pages || []).length; i++) {
    push('第' + (i + 1) + '集', 'https://api.example.com/play?aid=' + p.aid + '&cid=' + p.pages[i].cid);
}
if (p.season && p.season.episodes) {
    for (var j = 0; j < p.season.episodes.length; j++) {
        var e = p.season.episodes[j];
        push((j + 1) + ' ' + e.title, 'https://api.example.com/play?aid=' + e.aid + '&cid=' + e.cid);
    }
}
out;
</js>
```

### 5.5 HTML 型（仅在无 API 可用时）

```json
"ruleSearch":  { "bookList": "class.drama-card", "bookUrl": "tag.a@href", "name": "tag.a@text" },
"ruleToc":     { "chapterList": "@CSS:a.ep-item", "chapterName": "text", "chapterUrl": "href" },
"ruleContent": { "content": "@js:...从 result(html) 提取直链...", "sourceRegex": ".*\\.(m3u8|mp4|flv).*" }
```

`bookUrl` / `chapterUrl` 取相对链接即可（App 自动补全域名），但**必须保证相对链接带上必要的视图参数**（§4）。
苹果CMS 系（`ac=detail&wd=`、`vod_play_url`）与 MacCMS 系（`player_aaaa`、`url_next`）的规则细节见 §3.6，注意 `\/` 转义还原与多字段兜底。

### 5.6 发现页输入框（可选）

`exploreUrl` 支持 `<js>` 返回分类数组，其中可放控件：

```js
<js>
var key = String(infoMap.get('关键词或链接') || '');
var out = [
  {title:'关键词或链接', url:'', type:'text', viewName:"'🔎 关键词 / 分享链接'", 'default':key},
  {title:'🔍搜索', url:'', type:'button',
   action:"java.searchBook(infoMap.get('关键词或链接'), '示例视频源::https://api.example.com')"}
];
result = JSON.stringify(out);
result;
</js>
```

输入值存在 `infoMap`（按 `title` 作 key）；分类脚本结果有缓存，改控件值后需 `java.refreshExplore()` 清缓存重绘。

## 6. 绝对不能犯的错误

1. **URL 插值写错场合**：`{$.field}` 只用于 JSON 模式的规则字段，`searchUrl` 这类 URL 只认 `{{}}`。写错 → 字面量进 URL → 404 → 目录列表为空。
2. **JS 里用 `new URL()` / `document` / `fetch`**：Rhino 没有 → 执行报错被吞 → 获取播放地址失败。
3. **正文只取单一字段**：分集能播、电影全挂；必须多字段兜底。
4. **`<js>` 章节列表返回对象数组**：必须 `JSON.stringify` 每条。
5. **忘记 `bookSourceType: 4` 且分组不带关键词**：视频 Tab 不显示、路由错乱。
6. **把非直链文本当返回值**：HTML / 占位文本被当 URL 丢给播放器 → 转圈后停止。
7. **依赖 `startBrowser*` 或网页播放器**：会记成 `webPlayerUrl` → 嗅探失败 → 内置浏览器；本项目不以此为成功路径。
8. **把二级 m3u8 主清单当分片下载**：`#EXT-X-STREAM-INF` 开头的是主清单，分片在它指向的二级清单里。
9. **用父分类做苹果CMS 发现页**：父分类常 `total=0`，必须用子分类并逐个实测。
10. **只用「随手复制的链接」验证规则**：必须用书源实际拼出的 URL（含参数/请求头）验，并核对响应体积与特征字段（§4）。

## 7. 下载 / 缓存 / 多集

- 支持的流：单文件直链（Range 续传）、m3u8（含 AES-128、EXT-X-MAP、主清单跟随）。
- 10 并发分片下载、按序落盘到 `Download/A保存视频/<书名>/`；下载完成（mp4 落盘）后该集自动切换为本地播放。
- 切集/播完时先收尾上一集（补齐缺失片段后合并落盘），再开始当前集；边看边存遇到已下载的集直接跳过。
- 在线播放的分片写进 `VideoCache`（LRU 512MB），下载器取分片也走同一份——命中即零流量；缓存只作用于 http/https，**m3u8 清单不进缓存**（清单地址常带时效 token）；播放出错会自动回源 `FLAG_IGNORE_CACHE_ON_ERROR`。
- 目录一次拉全量即可，播放器分页懒解析并预取下一集；章节顺序即目录顺序。

## 8. 写完书源后的自查清单

1. 全文搜索书源 JSON：`startBrowser`、`data:`、`MPD`、`readBookConfig`、`Map("` —— 应为 **0 处**。
2. `bookSourceType == 4`；分组含「视频」。
3. `header` 是静态 JSON，含桌面 `User-Agent` + `Referer`；需要会话时 `enabledCookieJar: true`。
4. **用书源真实拼出的 URL + 书源 header** 实测三层：
   - 发现/搜索 URL → 200 且能解析出列表；
   - `bookUrl` 详情页 → 200 **且响应里确实有规则要匹配的字段/DOM**（对比体积与特征串，别只看状态码）；
   - 每个 `chapterUrl`（含同样的视图参数）→ 200 且响应能取到直链；
   - 只带 `Content-Type` 的最简请求测一遍 POST 接口，区分「规则问题」和「站点风控」。
5. 直链带书源 header 做 Range 请求：
   ```bash
   curl -s -o /dev/null -w '%{http_code} %{content_type}\n' \
     -A '<桌面UA>' -H 'Referer: <站点首页>' -H 'Range: bytes=0-32' '<直链>'
   ```
   期望 `206`/`200` 且内容开头是 `ftyp` 或 `#EXTM3U`。
6. 把直链套进 §2.4 的 `isPlayableUrl` 判定，确认为 `true`。
7. `ruleContent.content` 最终返回值确认是**单个字符串**，用 Node/curl 复刻一遍规则执行结果；确认以 `result = ...; result;` 收尾。
8. 目录/列表 `<js>` 返回值确认是 `JSON.stringify` 的字符串数组。
9. 多抽几集（不只第一集）+ 单集/电影类内容都能播；暂停退出再进进度正常。
10. 导入后从发现页点开：应直接进时光播放器播放，**不出现全屏网页浏览器**。
11. 若站点换域名/改 `bookSourceUrl`：书架老条目 `origin` 失效，需对那些书做一次换源。

调试技巧：报错弹窗里的「正文返回：xxx」就是规则实际返回值；用电脑 `curl`/Node 逐层模拟（页面 → 提取 → 拼接 → 清单）比反复手机导入快得多；播放失败时先确认流地址本身可访问。

## 9. 常见报错对照表

| 现象 | 真实原因 | 排查方向 |
|---|---|---|
| `目录列表为空` | `BookChapterList.kt:123` 抛 `TocEmptyException`；`bookUrl` 拼错/缺视图参数/被年龄门或验证页拦截、`ruleToc` 选择器不匹配、`<js>` 没返回数组 | 用书源真实 URL + header 实测，对比响应体积与特征 DOM；检查 `{$.field}` 插值、视图参数一致性（§4） |
| `获取播放地址失败` / `书源未拉起播放器，也没有返回播放地址。正文返回：（空）` | 正文规则抛错被吞或返回空 → `play()` 抛异常 | 检查 JS 语法/私有扩展/章节 URL 是否可请求；确认 `result = 直链` 写法；优先排查目录是否已为空 |
| 「可滑动屏幕右侧切换下一个视频」 | 错误卡片里的**界面提示文字**（`FullscreenVideoPlayer.kt:3536`），不是正文 | 别被误导，正文其实是空的 |
| 只闪一下封面 → 跳内置浏览器 | `fallbackIndex` → `play()` → `startBrowser(videoMode=true)` | 正文没返回直链；勾选「禁止弹出验证/内置浏览器」后该路径不再弹界面，改为失败提示 |
| `播放出错` / `Source error` | 地址已交给 ExoPlayer 但取流失败 | 直链 403（缺 Referer/桌面 UA）、格式不对、签名过期、返回了 MPD |
| 一直转圈 / 嗅探 20 秒后跳浏览器 | `webPlayerUrl` 被网页地址占用 | 书源调了 `startBrowser` 或返回了网页播放器页 |
| 搜索/发现页分类为空 | 列表规则解析失败，或接口硬风控（如 B 站 `-352`） | 换可用接口；确认 `<js>` 返回 `JSON.stringify` 数组 |
| 视频能播但下载的 mp4 打不开 | 主清单/二级清单问题或分片校验失败 | 确认是含分片列表的媒体清单，而非 `#EXT-X-STREAM-INF` 主清单 |

## 11. 给其它 AI 的复述模板（确认读懂了）

写书源前先回答；答不上来说明没读懂：

1. 时光播放器最终需要的是什么？（一个可直接交给 ExoPlayer 的流地址）
2. `isPlayableUrl` 认哪些后缀？（`.m3u8/.mp4/.m4v/.webm`，或含 `/m3u8/`、`authPath`、`.m3u8?`）
3. 正文里能不能出现 `java.startBrowser`？为什么？（不能，会被记成 `webPlayerUrl`，最终退回内置浏览器）
4. 章节 URL 能不能用 `data:`？（不能，`getStrResponseAwait` 不支持）
5. 为什么 `header` 要写桌面 UA + Referer？（CDN 防盗链，实测其它组合 403）
6. 目录 `<js>` 数组元素为什么要 `JSON.stringify`？（Rhino 对象无法被 `$.name` 取值）
7. HTTP 200 就代表能解析出目录吗？（不是，可能是年龄门/验证页；必须用书源真实 URL 核对响应体积与特征 DOM）
8. 目录和正文的章节 URL 为什么要带同一个视图参数？（否则正文请求拿到的是另一版页面）
9. 为什么优先用 JSON API 而不是页面 DOM？（DOM 随改版/参数变化，API 稳定）
10. POST 取流后为什么不要缓存直链？（`auth_key` 短时有效，正文每次播放都会重跑）
