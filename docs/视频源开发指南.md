## 1. 视频源是什么、如何被识别

视频源本质仍是 Legado 书源（`BookSource`），但书籍的"章节"是剧集，"正文"是播放地址。

### 1.1 识别口径（三重判定，满足其一即视为视频源）

App 按 `BookSourceExtensions.isVideoSource()` 与 `BookSourceDao.flowVideoSources()` 识别视频源，**两处口径必须一致**：

1. **显式类型**：`bookSourceType = 4`（推荐，最可靠）
2. **分组关键词**：`bookSourceGroup` 含以下任一关键词
   `视频` `影视` `电影` `剧集` `电视` `动漫` `短剧` `video` `movie`
3. **规则特征**：`ruleContent`（JSON 序列化后）含 `.m3u8` 或 `.mp4`

> **注意**：生态里大量视频源没有标 `bookSourceType=4`，只靠分组关键词兜底。
> **新写源请务必同时做两件事**：`bookSourceType` 设为 `4`，分组名带上"视频"或"影视"。
> 只标类型不带关键词也能被识别，但反过来（只靠规则特征）最脆弱。

### 1.2 被识别为视频源后

- 底部导航出现「视频」Tab，发现页按 `flowVideoSources` 列出所有视频源
- 点书籍直接进**时光播放器**（不经过详情页/阅读页），返回回到视频主页
- 支持竖滑切集、选集面板、进度记忆、下载（多线程+断点续传）、边看边存

## 2. 三种播放链路（源的类型）

App 每次播放一集时会执行一次正文规则并按返回结果自动分发（`VideoSourcePlayer.resolveChapter`）：

### 类型 A：章节地址即直链（最简单）

目录规则的 `chapterUrl` 直接就是 `m3u8/mp4` 地址。

```json
"ruleToc": {
  "chapterList": "...",
  "chapterName": "text",
  "chapterUrl": "href"    // href 本身是 https://xxx/index.m3u8
}
```

正文规则可不写。App 直接交给 ExoPlayer，自动携带书源 `header` 里的请求头。

### 类型 B：正文规则返回直链（推荐）

正文规则经过计算后**直接返回** `m3u8/mp4` 地址字符串。App 会从返回文本中提取直链
（`VideoSourcePlayer.extractPlayableUrl`），成功后用 ExoPlayer 播放。

适用：苹果CMS API 型（非凡等）、网页 HTML 中嵌有流地址的站点（茶杯狐的 `player_aaaa`）。

```js
// ruleContent 示例：返回纯 m3u8 地址
@js:
var m = html.match(/"url":"([^"]+)"/);
pUrl = m[1].replace(/\\\//g, '/');
pUrl;   // 直接返回 https://xxx/index.m3u8
```

### 类型 C：网页播放器型（兜底）

正文规则执行时通过 `java.startBrowser(url)` 或 `java.startBrowserAwait(url, title)`
拉起站点自己的网页播放器。App 会**拦截**这个动作，拿到地址后以**全屏视频模式 WebView**
打开（无标题栏、沉浸式、自动注入文案汉化脚本）。

```js
@js:
java.startBrowserAwait(pUrl, title);   // 引擎拦截后不会真开浏览器
'请刷新查看内容';                       // 返回值无所谓
```

适用：流地址需要 JS 运行时才能拿到、或有防盗链跳转的站点。

> **三种类型的判定顺序**：规则返回的文本里能提取到直链 → 类型 B；
> 规则执行期间拉起了浏览器 → 记录地址，若是直链按 B 处理，否则按 C；
> 都没有 → 走传统解析链路（mpd 文本/正文求值），最后退回 `play()` 让书源自己拉起。

### 类型 C 的特殊变体："先种缓存、刷新再拉起"型

有的源（如茶杯狐原版规则）第一次执行正文只做初始化，返回"请刷新查看内容"占位文本，
**第二次执行**才 `startBrowserAwait`。App 已内置兼容：第一次什么都没拿到时会
**自动补执行一次**（模拟刷新）。写这类源可以照旧，但更推荐改成类型 B 直接返回直链。

## 3. 支持的规则格式与语法

### 3.1 JS 引擎是 Rhino，不是浏览器

这是**最重要的认知**。规则里的 JS 运行在 Rhino 引擎上：

| 写法 | 可用性 | 说明 |
|---|---|---|
| `var`、`function`、`String`、`RegExp` | ✅ | ES5 全部可用 |
| `match`、`replace`、`split`、`indexOf`、`substring`、`lastIndexOf`、`split` | ✅ | 字符串/数组 ES5 方法 |
| `JSON.parse` / `JSON.stringify` | ✅ | |
| `java.xxx`（ajax、startBrowser 等）、`cache.get/put`、`baseUrl`、`result`、`book`、`title`、`cookie` | ✅ | 引擎注入的绑定变量 |
| `new URL(url, base)` | ❌ **不存在** | Rhino 没有浏览器 URL API，用了直接报错 |
| `includes`、`find`、`startsWith`（数组上） | ⚠️ 部分 ES6，勿依赖 | 用 `indexOf(...) >= 0` 代替 |
| 箭头函数 `=>`、模板字符串 | ⚠️ 部分可用，不保证 | 建议用 `function`/字符串拼接 |
| `fetch`、`XMLHttpRequest`、`document`、`window` | ❌ | 用 `java.ajax(url)` 发请求 |

**相对地址补全域名**（代替 `new URL`）：

```js
var base = String(baseUrl);                 // baseUrl = 当前页面地址
var cut = base.indexOf('/', 8);             // 跳过 https:// 找第一个 /
var root = cut > 0 ? base.substring(0, cut) : base;
var abs = root + relativePath;              // 相对路径以 / 开头时适用
```

### 3.2 URL/字段中的插值语法（极易混淆，重点）

| 写法 | 用在哪 | 效果 |
|---|---|---|
| `{$.field}` | **规则字段**（如 `ruleSearch.bookUrl`） | ✅ JSON 模式下内嵌 JSONPath 取当前条目字段 |
| `{{js代码}}` | `searchUrl`/`exploreUrl` 里 | ✅ 内嵌 JS（`{{key}}`、`{{page}}` 也是这个机制） |
| `{{$.field}}` | URL 的 `{{}}` 里 | ❌ 无效（`$.` 不是合法 JS） |
| `{$.field}` 写在 `searchUrl` 里 | | ❌ 无效（那是 URL 规则，只认 `{{}}`） |

**从搜索/发现结果构造详情 URL 的正确写法**（JSON API 源）：

```json
"bookUrl": "https://api.xxx.com/api.php/provide/vod/?ac=detail&ids={$.vod_id}"
```

原理：搜索结果条目使规则进入 JSON 模式，`{$.vod_id}` 由 AnalyzeByJSonPath 的
内嵌规则机制（平衡匹配 `{...}`）替换为条目里的 `vod_id` 值。

### 3.3 JS 章节列表的返回值

`ruleToc.chapterList` 用 `<js>...</js>` 返回数组时，**条目必须是 JSON 字符串**，
后续 `chapterName: "$.name"` 才能可靠解析：

```js
// ❌ 返回 Rhino 对象数组：$.name 在 NativeObject 上会取不到
out.push({ name: nm, url: ul });

// ✅ 返回 JSON 字符串数组
out.push(JSON.stringify({ name: nm, url: ul }));
```

`chapterList` 的 JS 里 `result` 是目录页原始响应文本（字符串），JSON API 直接
`JSON.parse(result)` 即可。

### 3.4 页面字段兜底（真实教训）

同一个站点，**分集页和电影页的播放器数据字段可能不同**。例如茶杯狐：

- 分集动漫页：`"url_next":"https://xxx/index.m3u8"`（有值）
- 电影页：`"url_next":""`（空），流地址在 `player_aaaa` 配置的 `"url"` 字段里

规则必须**多字段兜底**，只依赖单一字段会导致某类内容全部解析失败。

## 4. 完整模板

### 模板一：苹果CMS API 型（JSON）——参考 `视频源/非凡影视.json`

```json
{
  "bookSourceUrl": "https://api.xxx.com",
  "bookSourceName": "某某影视(视频源)",
  "bookSourceGroup": "视频·影视",
  "bookSourceType": 4,
  "enabled": true,
  "enabledExplore": true,
  "header": "{\"User-Agent\":\"Mozilla/5.0 ... Mobile Safari/537.36\",\"Referer\":\"https://播放域名/\"}",
  "searchUrl": "https://api.xxx.com/api.php/provide/vod/?ac=detail&wd={{key}}&pg={{page}}",
  "exploreUrl": "国产动漫::https://api.xxx.com/api.php/provide/vod/?ac=detail&t=29&pg={{page}}\n短剧::https://api.xxx.com/api.php/provide/vod/?ac=detail&t=36&pg={{page}}",
  "ruleSearch": {
    "bookList": "$.list[*]",
    "name": "$.vod_name",
    "coverUrl": "$.vod_pic",
    "bookUrl": "https://api.xxx.com/api.php/provide/vod/?ac=detail&ids={$.vod_id}"
  },
  "ruleBookInfo": {
    "name": "$.vod_name",
    "intro": "$.vod_content##<[^>]*>##"
  },
  "ruleToc": {
    "chapterList": "<js>...解析 vod_play_url，push(JSON.stringify({name,url}))...</js>",
    "chapterName": "$.name",
    "chapterUrl": "$.url"
  },
  "ruleContent": {
    "content": "<js>...返回直链或 startBrowserAwait...</js>",
    "sourceRegex": ".*\\.(m3u8|mp4|flv).*"
  }
}
```

苹果CMS 约定：`ac=detail&wd=关键词` 搜索；`ac=detail&t=分类id` 分类浏览；
`vod_play_url` 格式为 `线路1$$$线路2`，每线路内 `第01集$地址#第02集$地址`。

### 模板二：网页 HTML 型（CSS 选择器 + JS 提取）——参考 `bookSource_茶杯狐狸_修复.json`

```json
"ruleSearch":  { "bookList": "class.stui-vodlist[0]@tag.li", "bookUrl": "tag.a@href", ... },
"ruleToc":     { "chapterList": "id.playlist1@tag.ul@tag.li", "chapterName": "tag.a@text", "chapterUrl": "tag.a@href" },
"ruleContent": { "content": "@js:...从 result(html) 提取直链...", "sourceRegex": ".*\\.(m3u8|mp4|flv).*" }
```

要点：
- `bookUrl`/`chapterUrl` 直接取页面相对链接即可（App 会自动补全域名）
- 正文 JS 里 `result` 是播放页 HTML、`baseUrl` 是播放页地址
- MacCMS 系站点流地址通常在 `player_aaaa={...}` 或 `"url_next":"..."` 里，注意 `\/` 转义还原

## 5. 绝对不能犯的错误

以下每一条都是本项目实际踩过并修复过的坑：

1. **❌ 在 URL 字段里用 `{{$.field}}` 或 `{$.field}` 不分场合**
   `{$.field}` 只在 JSON 模式的规则字段里有效；`searchUrl` 这类 URL 只认 `{{}}`。
   写错的表现：URL 带着字面 `{$.vod_id}` 去请求 → 404 → **目录列表为空**（搜索结果却正常显示，极具迷惑性）。

2. **❌ JS 里用 `new URL()`、`document`、`fetch` 等浏览器 API**
   Rhino 没有。表现为执行时报错 → **获取播放地址失败**。

3. **❌ 正文规则只取单一字段**（如只取 `url_next`）
   分集内容正常、电影/单集内容全挂。必须多字段兜底（`url_next` → `player_aaaa.url` → 通用正则）。

4. **❌ JS 章节列表返回对象数组**
   `chapterName: "$.name"` 在 Rhino 对象上取不到值 → 章节名/地址全空。
   必须 `JSON.stringify` 每个条目。

5. **❌ 忘记设置 `bookSourceType: 4` 且分组名不带关键词**
   源能导入、能搜索，但视频 Tab/发现页不显示、播放路由也可能错乱。

6. **❌ 在正文规则里对非直链地址直接当返回值**
   返回 HTML 或占位文本会被当 URL 丢给播放器 → 转圈后停止。
   直链走直链分支，网页走 `startBrowserAwait`，占位文本要保证**第二次执行**能拉起播放器。

7. **❌ 把二级 m3u8 清单当分片下载**（App 下载器已内置主清单支持，但自写解析时注意）
   `#EXT-X-STREAM-INF` 开头的是主清单，真正的分片在它指向的二级清单里。

8. **❌ 用 `type_id` 父分类做发现页**
   苹果CMS 的父分类（如 `t=1 电影片`）经常 `total=0`，必须用子分类（动作片 6、国产剧 13 等）。发布前逐个分类实测。

## 6. 需要注意的事项

### 请求头与防盗链

- `header` 字段写完整 JSON 字符串：UA 建议手机 UA；m3u8/分片普遍校验 `Referer`，填站点播放页域名
- App 播放直链时会**自动带上书源 header**，所以 header 写对，直链才能播
- 需要会话 Cookie 的源开启 `"enabledCookieJar": true`

### sourceRegex

`ruleContent.sourceRegex`（如 `.*\.(m3u8|mp4|flv).*`）用于校验正文提取结果，
建议写上，能防止网页文本被误当播放地址。

### 占位/刷新型源的约定

如果正文第一次返回占位文本，必须保证：
- 用 `cache.put(key, value, 有效期秒)` 记录初始化标记（`cache` 由引擎注入）
- 第二次执行时 `cache.get(key)` 命中后调用 `java.startBrowserAwait(pUrl, title)`
- `pUrl` 必须在每次执行时都能重新计算出来（不要依赖第一次的局部变量）

### 多集与目录

- 目录一次拉全量即可，播放器分页懒解析（滚到哪集解析哪集，并预取下一集）
- 章节顺序 = 目录顺序；进度按 `bookUrl + 章节序号` 记忆
- 竖滑切集需要目录有 ≥2 集；单集电影也完全支持播放

### 下载/边看边存

- 支持的流：单文件直链（Range 续传）、m3u8（含 AES-128、EXT-X-MAP、主清单跟随）
- 10 并发分片下载、按序落盘；保存到 `Download/保存视频/<书名>/`
- 网页播放器型（类型 C）的集**无法下载**，规则里尽量给出直链
- 下载完成（mp4 落盘）后该集**自动切换为本地播放**，不再联网缓冲；
  边看边存遇到已下载的集直接跳过，不会重复缓存
- 切集/播完时先**收尾上一集**（补齐缺失片段后合并落盘），再开始当前集

### 播放与下载共用一份缓存

- 在线播放时的分片会写进 `VideoCache`（`SimpleCache`，LRU 512MB，位于 app 缓存目录），
  下载器取分片/直链也走同一份——命中即零流量，未命中才联网，联网结果同样进缓存
- 于是边看边存基本不再产生额外流量：看过的部分已在缓存里，只需补齐没看过的尾巴
- 缓存只作用于 http/https：本地 mp4 走系统数据源，不会被复制一份进缓存
- m3u8 **清单不进缓存**（站点常在清单地址带时效 token，缓存旧清单会拿到过期分片）；
  清单体积很小，重复取的代价可忽略
- 播放侧出错会自动回源（`FLAG_IGNORE_CACHE_ON_ERROR`），缓存损坏不会导致播放失败

### 稳定性建议

- 资源站换域名频繁：把域名类参数集中在规则开头或用 `bookSourceUrl` 变量，便于批量替换
- 同一站点多线路时优先选 m3u8 线路（直链可下载、可竖滑）
- 发现页分类宁多勿少，但每个都要实测能出数据

## 7. 报错信息对照表

| 报错 | 根因 | 排查方向 |
|---|---|---|
| `目录列表为空` | `bookUrl`/`tocUrl` 规则错误，或 URL 插值写错 | 检查 `{$.field}`/`{{}}` 用法；直接浏览器访问 bookUrl 看是否 404 |
| `获取播放地址失败` + `正文返回: xxx` | 正文规则返回的不是直链，书源也没拉起播放器 | 看正文返回了什么：占位文本→刷新机制问题；报错→JS 语法/API 问题 |
| `书源未拉起播放器，也没有返回播放地址` | 兜底 `play()` 也没成功 | 同上，重点检查规则 JS 是否抛异常 |
| 搜索/发现正常，点开就报错 | 多半是 `bookUrl` 构造问题（搜索结果来自列表本身） | 用 §5 第 1 条 |
| 转圈后停止、无弹窗 | 规则返回了非直链文本被当 URL 播放 | 检查正文返回值 |
| 视频能播但下载的 mp4 打不开 | 主清单/二级清单问题或分片校验失败 | 确认是媒体清单（含分片列表）而非 `#EXT-X-STREAM-INF` 主清单 |

## 8. 调试与自检清单

发布源之前逐项检查：

- [ ] `bookSourceType: 4` + 分组名含"视频/影视"等关键词
- [ ] `searchUrl` 搜索有结果、封面/书名正常
- [ ] **点开书籍能出目录**（这一步最常出问题）
- [ ] 分集内容：每一集都能播放（多抽几集，不只第一集）
- [ ] **单集/电影类内容也能播放**（字段兜底是否生效）
- [ ] 发现页每个分类都能出数据（父分类陷阱）
- [ ] 播放中途暂停/退出再进，进度记忆正常
- [ ] 下载一集 → 缓存的 mp4 能独立播放
- [ ] 换一个分类再播放同一视频，竖滑列表跟随新分类
- [ ] 规则 JS 全部用 ES5 写法（无 `new URL`、无依赖 ES6 数组方法）

调试技巧：
- 报错弹窗里的"正文返回：xxx"就是规则的实际返回值，直接对着它分析
- 用电脑 `curl`/Node 模拟规则逻辑逐层验证（页面 → 提取 → 拼接 → 清单），比在手机上反复导入快得多
- 播放失败时先确认流地址本身可访问（可能只是资源站挂了或换域名）
